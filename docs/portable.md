# Переносимый «Своё Вино»

Архив содержит готовый `dist/` (HTML, CSS, JavaScript и PWA), FastAPI, каталог 2 103 вин, чистую схему базы и полный исходный код приложения в `source/`. Для фронтенда не нужен Node.js и отдельная сборка. Распознавание работает через RunPod; локальный ML-пайплайн и веса модели в архив не входят. В чистой базе нет эталонных фотографий каталога, поэтому карточки показывают встроенную заглушку до подключения существующего датасета.

## Что входит в архив

- `dist/` — готовый фронтенд, который сразу отдаёт сервер; `backend/` — рабочий код API и админки.
- `source/wine_server/static/mobile/` — **весь исходный код фронтенда** (HTML, CSS, JavaScript, PWA, шрифты и изображения интерфейса); `source/wine_server/static/admin/` — исходники админки.
- `source/wine_server/` — остальной код сервиса, тесты и вспомогательные скрипты; `source/wine_curation/` — код разметки; `source/wine_dataset/collector/` — код сбора каталога. Каталог для чистого запуска лежит в `seed/catalog.csv`.
- `source/wine_server/deploy/` — исходные примеры Nginx, systemd и обновления сертификата для текущего VPS. Если используете их на другом сервере, сначала замените домен, пути и порт; для обычного запуска достаточно `start.sh` и прокси из примера ниже.

Локальные `models/`, веса, `inference.py`, `ranking_core.py` и скрипты экспорта/проверки локальной модели исключены: на новом сервере распознавание выполняет RunPod. Старый `deploy/publish.sh` тоже не включён: он обновлял локальный ML и был привязан к текущему VPS. Пользовательские фото, история, база, разметка и секреты также не входят в ZIP. `start.sh` запускает готовые `backend/` и `dist/`; редактирование файлов в `source/` не меняет уже запущенные копии. Чтобы снова собрать архив после правок исходников, выполните `python3 source/wine_server/deploy/portable/build_portable.py wine-portable-updated.zip` из распакованной папки.

## Запуск

На Linux с Python 3.10–3.13, модулем `venv` и доступом к PyPI:

Если проект уже развернут в корне Git-репозитория, запустите `bash start.sh` из этого каталога. Для архива:

```bash
unzip wine-portable.zip
cd wine-portable
bash start.sh
```

Если на сервере нет `unzip`, распакуйте тем же Python, который нужен для запуска:

```bash
python3 -m zipfile -e wine-portable.zip .
cd wine-portable
bash start.sh
```

Первый запуск создаёт `.venv/`, `data/` и приватный `.env` с новым паролем админки. Пароль выводится один раз, если запуск идёт из терминала; позже он находится в `.env` с правами `600`. При следующих запусках существующие база, каталог, снимки, история и разметка не заменяются. Админка открывается по `/admin/`, проверка состояния — `/health`.

В начале `start.sh` можно изменить:

| Переменная | Что задаёт |
| --- | --- |
| `FRONTEND_URL` | Публичный адрес сайта, например `https://wine.example.com` |
| `BACKEND_URL` | Публичный адрес API. Он должен совпадать с `FRONTEND_URL`: фронтенд обращается к `/api` на том же адресе |
| `RUNPOD_URL` | Адрес пода; сервер вызывает `POST /v1/search`, браузер напрямую к поду не обращается |
| `BACKEND_BIND_HOST`, `BACKEND_BIND_PORT` | Локальный адрес и порт FastAPI |
| `DATA_ROOT` | Родительский каталог для `wine_dataset/` и `wine_media/` |
| `TLS_CERT_FILE`, `TLS_KEY_FILE` | Необязательные пути к сертификату и ключу для прямого HTTPS |

Значения можно передавать переменными окружения без редактирования файла. Для запуска на текущем порту 8100 за локальным HTTPS-прокси установите `FRONTEND_URL=BACKEND_URL=https://ваш-домен`, а `BACKEND_BIND_HOST` оставьте `127.0.0.1`; прокси должен передавать весь сайт на `http://127.0.0.1:8100` с исходным заголовком `Host`. Например, Caddy:

```caddyfile
wine.example.com {
    reverse_proxy 127.0.0.1:8100
}
```

Для прямого доступа можно задать `BACKEND_BIND_HOST=0.0.0.0`, `FRONTEND_URL=BACKEND_URL=http://IP:8100`. Загрузка фото работает по HTTP, но камера телефона и установка PWA на удалённом устройстве требуют HTTPS. С готовым TLS-сертификатом можно указать `TLS_CERT_FILE` и `TLS_KEY_FILE`, публичный URL `https://...` и порт, доступный извне. `start.sh` запускает API и `dist/` одним процессом.

## GigaChat и секреты

В публичном ZIP **нет** ключа GigaChat, пароля админки, пользовательской базы, сканов, фотографий и разметки. После распаковки создайте `.env` из `.env.example` или передайте переменные окружения:

```bash
cp .env.example .env
chmod 600 .env
# Впишите WINE_GIGACHAT_AUTH_KEY и WINE_GIGACHAT_CLIENT_ID,
# затем снова запустите ./start.sh.
```

Помощник без этих двух значений запускается с подбором по каталогу. Для реальных ответов GigaChat дополнительно нужен доверенный корневой сертификат НУЦ Минцифры. Установите его в системное хранилище либо укажите путь к PEM-файлу в `WINE_GIGACHAT_CA_BUNDLE` в `.env`; TLS-проверка остаётся включённой. [Инструкция GigaChat по сертификатам](https://developers.sber.ru/docs/ru/gigachat/certificates).

Если RunPod требует bearer-токен, положите `WINE_ML_API_KEY` в `.env`. Секреты не копируйте в `start.sh` и не публикуйте вместе с распакованной папкой. `.gitignore` исключает `.env`, `data/` и `.venv/` при работе с Git.

## Перенос существующих данных

Для обновления на том же сервере укажите `DATA_ROOT` на существующий родительский каталог, содержащий `wine_dataset/` и `wine_media/`. Скрипт не заменяет `collector/state.sqlite3`, каталог, снимки или разметку. Перед переносом на другой сервер сделайте согласованную копию SQLite и медиафайлов. Старые строки базы хранят абсолютные пути к фото, поэтому при смене расположения каталогов их надо перенести с сохранением прежнего пути либо отдельно мигрировать эти пути. **Не** заливайте публичный чистый архив поверх действующей базы: храните данные отдельно и делайте резервную копию перед обновлением.

Для изолированной проверки с уже установленными Python-зависимостями можно передать `WINE_PYTHON=/путь/к/venv/bin/python`; тогда `start.sh` не создаёт собственную `.venv` и не вызывает pip.
