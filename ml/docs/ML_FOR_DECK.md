# ML-часть для презентации: сканер российских вин

Коротко и с цифрами — всё, что нужно для слайдов про распознавание. Подробности:
`qwen_finetune/STATUS_gpu_runs_20260929.md`, `docs/findings.md`, `service/DEPLOY.md`.

## Задача

Пользователь фотографирует бутылку в магазине — сервис за ~1 секунду находит это вино в каталоге
«Своё Вино» из **2103 позиций** и отдаёт карточку. Сложность: много почти одинаковых этикеток
(одна винодельня, одна линейка, разный сорт или год), фото с полки — под углом, с бликами, с соседями
в кадре.

## Результат

| Метрика | Значение |
|---|---|
| Точность top-1 (379 реальных фото) | **93.4%** |
| Правильное вино в top-5 | **98.9%** |
| Кадры организаторов / наши старые / наши новые | 95.8% / 96.5% / 86.1% |
| Если дубли каталога (одна бутылка под двумя slug) считать одним вином | 94.2% (уникальные кадры) |
| Время ответа, от отправки фото до slug | ~1.2 с на GPU |
| Покрытие каталога | 2103 из 2103 вин |

Проверено сквозным прогоном через HTTP тем же способом, что скрипт оценки организаторов, и
прогоном самого скрипта организаторов (`eval_results/predictions.jsonl`).

## Как работает (схема для слайда)

```
фото с телефона ──► Qwen3-VL-Embedding-8B + наш LoRA ──► вектор 4096
                     (целый кадр, 2560 визуальных токенов)          │
                                                                    ▼
каталог: 2103 вина × несколько фото (4093 эталона) ──► ближайшее вино (косинус,
         заранее посчитанные векторы                     максимум по фото вина)
                                                                    │
                                                                    ▼
                                               slug + карточка + 4 альтернативы
```

1. **Модель** — мультимодальный эмбеддер Qwen3-VL-Embedding-8B, дообученный нами LoRA-адаптером
   на парах «реальное фото ↔ фото из каталога».
2. **Индекс** — у вина несколько эталонов: основное фото каталога плюс доп. фото (бутылка,
   фронтальная этикетка). Похожесть вина = лучшее совпадение среди его фото.
3. **Запрос** — фото целиком в высоком разрешении (2560 токенов), без вырезания этикетки: модель
   читает мелкий текст (сорт, год, сладость) сама.
4. **«Вина нет на фото»** — если похожесть с лучшим вином ниже 0.60, сервис может ответить «не
   найдено» (на тесте 0 из 379 фото вина потеряно, 147 из 152 посторонних фото отсечено).

## Путь к результату (что пробовали)

| Шаг | Что дало |
|---|---|
| SigLIP2 + индекс по фото каталога (первая версия) | базовый уровень, работает на CPU |
| Переход на Qwen3-VL-Embedding-8B + дообучение LoRA | основной скачок качества |
| Запрос в высоком разрешении (2560 токенов), эталоны 1024 | лучше, чем 1024 для запроса |
| **Несколько фото на вино в индексе** | **+3.4 п.п.**, значимо (14 исправлено / 1 сломано) |
| Чистка каталога: 16 вин с чужим фото, 20 вин без фото | все 2103 вина находятся по своему фото |

## Что проверили и отклонили (честно, с цифрами)

| Идея | Результат |
|---|---|
| Реранкер Qwen3-VL-Reranker-8B | хуже (3 исправлено / 10 сломано) и в 5 раз медленнее |
| LLM «читает этикетку» (Qwen3-VL-8B-Instruct) | 82.6% — хуже, уверенно ошибается |
| Вырезать этикетку детектором YOLO | 81.8% — теряется контекст бутылки |
| Запрос в низком разрешении (1024) | значимо хуже 2560 |
| Дообучение на 305 интернет-фото (v3) | 93.1% против 93.4% — без прироста |
| Интернет-фото как доп. эталоны | 0 изменений |
| Трюки с индексом (центроиды, CSLS и др.) | не лучше максимума по фото |

Все сравнения — попарно на одних и тех же кадрах, с правилом значимости
|исправлено − сломано| ≥ 2·√(исправлено + сломано).

## Работа с данными

- **Тест:** 379 реальных фото (наши снимки в магазинах + фото организаторов), 137 вин;
  дедупликация по SHA-256 — 347 уникальных. Тест не пересекается с обучением и индексом.
- **Каталог:** найдены и исправлены 16 вин, у которых в каталоге стояло фото другого вина
  (например, у Az Abrau Баяншира — фото Мадрасы); вручную найдены фото для 20 вин без фото.
- **Дубли каталога:** 55 групп (115 slug), где одна бутылка записана под разными slug
  (разный год/крепость) — по фото их не различить, это ограничение каталога.

## Где ошибается

Почти все ошибки — соседи по линейке одной винодельни с почти одинаковыми этикетками
(например, Бельбек Мускат / Пино Нуар, KAFFA Каберне Фран / Саперави). В 21 из 25 ошибок
верное вино стоит в top-5 — интерфейс показывает альтернативы, пользователь выбирает в один тап.

## Продакшн

- API: `POST /v1/eval/predict` → `{"slug": ...}` (контракт организаторов),
  `POST /v1/search` → карточка вина, 4 альтернативы, уверенность, признак «вина нет».
- Запуск из репозитория: `bash setup.sh && bash start.sh`; нужен GPU от 24 ГБ видеопамяти.
- Добавить новое вино или фото — без переобучения: фото в индекс, `python build_index.py`
  (секунды).
