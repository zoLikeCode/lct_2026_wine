# Qwen3-VL-Embedding + LoRA: GPU-прогоны 27–29 сентября

Статус работ после §11.45–11.46 findings. Все прогоны — на RunPod A100 80GB, сравнение попарное
по правилу §11.37: значимо при |исправлено − сломано| ≥ 2·√(исправлено + сломано).
Production-адаптер — `v2/best`; попытка дообучения v3 (ниже) его не превзошла.

## Итог

**Production-конфигурация:** Qwen3-VL-Embedding-8B + LoRA v2, эталоны на 1024 визуальных токенах,
**несколько эталонов на вино** (основной + доп. фото каталога `_bottle` / `_front_label`, берётся
максимум схожести), запрос — целый кадр на 2560 токенах, без реранкера и без детекции этикетки.

| Тест | Кадров | top-1 | top-5 |
|---|---:|---:|---:|
| Расширенный тест (наши + организаторов + новые) | 379 | **93.4%** | 98.9% |
| — без 5 кадров-дублей каталога (правило §11.33) | 374 | **94.7%** | — |

Латентность одного запроса на A100: ~0.68 с (эмбеддинг кадра на 2560) + поиск по индексу.

**«На фото нет вина»:** если схожесть кадра с лучшим эталоном ниже **0.60**, сервис отвечает
`{"slug": null}`. На наших данных порог не теряет ни одного фото вина и отсекает 97% фото без вина
(подробности ниже). Формат ответа для такого случая нужно подтвердить у организаторов.

## Что сделано

1. **Индекс достроен до всех 2103 вин.** 19 эталонов добавлены вручную по витринным фото
   (`refs_manual.csv`), последний, «Method Classic Кокур», добавлен 29.09 по полевому фото — каталог покрыт полностью (2103);
   `build_index.py` докодирует новые эталоны сам, не трогая кеши. Гарантированных
   промахов в тесте больше нет: «Олег» и «Розовое золото» находятся.
2. **Тест расширен с 257 до 379 кадров.** Добавлены 122 новых снимка команды из выгрузок
   `wine_real_yolo_20260928*` (новые по SHA-256, в обучение и индекс не попадали, все slug есть в
   каталоге). Исключены 3 кадра Перовских (правка Никиты) и 3 кадра Мезыбь IMG_1653–1655 (на этикетке
   «Каберне Совиньон, Каберне Фран, Мерло 2019» — такой позиции в каталоге нет).
3. **Прогоны:**

| Прогон | Что проверяли | Результат |
|---|---|---|
| hires (257 кадров) | эталоны/запрос 1024 vs 2560 | 1024×2560: 96.1% против 94.6%, 4/1 — шум, но лучший |
| rerank (257) | Qwen3-VL-Reranker-8B по top-5 | 93.4%, 3/10, ~3.4 с/кадр — **отклонён** |
| run1 (379) | вырезка этикетки (ручная рамка / YOLO), несколько эталонов | **несколько эталонов: 93.4%, 14/1 — значимо лучше**; YOLO-вырезка 81.8%, 2/33 — значимо хуже; ручная рамка + кадр 4/0 — в проде рамок нет |
| run2 (379) | 1024 vs 2560 с доп. эталонами; Qwen3-VL-8B-Instruct как «читатель этикетки» | запрос 1024: 2/10 — значимо хуже; 1024+2560: шум; **читатель 82.6% при пороге 0.8, 10/51 — отклонён** |
| офлайн (379) | трюки с индексом на готовых векторах: среднее top-2 эталонов, центроид, поправка на «хабы» (CSLS), плотность | всё не лучше максимума по эталонам (шум или хуже) |
| v3 (379) | дообучение адаптера v2 на 305 интернет-фото в реальной обстановке + доп. фото каталога + трудные соседи, запрос 2560 | 93.1% против 93.4%, 5/6 — шум; **отклонён** (см. ниже) |
| no-wine | порог схожести «вина нет» на 150 фото COCO + 2 фото сока | порог 0.60: 0/379 фото вина потеряно, 147/152 отсечено |

4. **Проверка на утечку.** Тестовые кадры не совпадают ни с обучением, ни с индексом (SHA-256 и
   dHash). Знакомство адаптера с вином не даёт преимущества: вина, которых не было в обучении LoRA,
   распознаются не хуже (94.1% против 91.8%).

## Дообучение v3: почему не взяли

Старт с адаптера v2, lr 2e-5, 54 шага (1 эпоха): запросы — 305 интернет-фото в реальной
обстановке (×2), 800 доп. фото каталога, 300 имитаций полки; 3 трудных негатива-соседа на запрос;
запрос 2560 токенов, эталоны 1024. Чекпоинт выбирался по 78 отложенным интернет-фото 62 вин
(разбиение по винам) — на них v3 не обогнал v2 ни на одном шаге (92.3% → 92.3% / 91.0% / 92.3%).
Проверка финального чекпоинта (эпоха 1) на тесте:

| Набор | v2 | v3 |
|---|---:|---:|
| наши старые снимки (201) | 96.5% | 96.0% |
| новые снимки (122) | 86.1% | **88.5%** |
| кадры организаторов (56) | **98.2%** | 92.9% |
| всего (379) | **93.4%** | 93.1% (5 исправлено / 6 сломано — шум) |

v3 чуть лучше на новых снимках, но теряет 3 кадра организаторов (Formula Q ×2, Жемчужная) — а они
ближе всего к настоящему тесту. Вывод: 305 интернет-фото мало, чтобы дообучение дало прирост;
дальше упираемся в данные, а не в модель. Контроль пайплайна: пересчёт v2 с нуля совпал с кешами
прошлых прогонов покадрово (0/0).

## «На фото нет вина»

Сигнал — схожесть кадра с лучшим эталоном каталога (та же, по которой выбирается вино), считается
бесплатно. Проверка `nowine_check.py` на 150 случайных фото COCO и 2 фото сока (адаптер v2):

| Порог | фото вина отклонено (из 379) | фото без вина отсечено (из 152) |
|---:|---:|---:|
| 0.55 | 0 | 117 |
| **0.60** | **0** | **147** |
| 0.65 | 0 | 152 |
| 0.69 | 1 | 152 |
| 0.75 | 6 | 152 |

Максимум у фото без вина — 0.64, минимум у фото вина — 0.69. Выбран порог **0.60** (запас 0.09 до
самого слабого фото вина). Не проверено: бутылки других напитков на полке (пиво, водка, сок,
газировка) — стакан сока дал 0.59, почти на пороге. Нужно 15–20 таких фото; если они окажутся
выше порога — добавить текстовую проверку «бутылка вина vs другой напиток» тем же эмбеддером.
Открытый вопрос к организаторам: будут ли в тесте фото без вина и какой ответ правильный.

## Почему общая цифра ниже прежних 96%

Качество на старых наборах не изменилось (наши 201 — 96.0%, организаторов 56 — 96.4%). Просадка —
только на 122 новых кадрах (77% с одним эталоном, 86% с несколькими), и она сосредоточена в 9 винах
из 58 из-за серий по 4–8 снимков одной бутылки:

- **Brut d'Or Blanc de Blancs (4 кадра), ZB Frizzante Semi-Dry Rose (1 кадр)** — дубли каталога
  (одно вино под двумя slug), неразрешимы; нужно внести в `field_label_corrections.csv` как exclude;
- **Мезыбь «Каберне Совиньон, Каберне Фран» (4 кадра)** — модель везде отвечает «Мерло», вероятна
  ошибка разметки, нужен аудит по правилам §11.33;
- остальное — соседи по линейке (Бельбек Мускат/Пино Нуар, KAFFA Каберне Фран/Саперави, Собер Баш
  Ркацители/Рислинг, Adagum Odessa Black/Каберне); у 21 из 25 ошибок верное вино в top-5.

Старый тест слегка оптимистичен по двум причинам: его разметку правили после разбора ошибок модели, и
39 кадров в нём — один снимок в двух наборах.

## Что отклонено и почему

- **Реранкеры (Qwen3-VL-Reranker-8B, Qwen3-VL-8B-Instruct без дообучения)** — ломают больше, чем
  чинят, и уверенно ошибаются (у читателя 60% неверных ответов с уверенностью ≥ 0.95).
- **Вырезка этикетки детектором YOLO** — теряет контекст бутылки, значимо хуже целого кадра.
- **Запрос на 1024** при нескольких эталонах — значимо хуже 2560.
- **Адаптер v3** (дообучение на 305 интернет-фото) — шум на тесте, теряет кадры организаторов.
- **Трюки с индексом** (центроиды, среднее top-2, поправка на «хабы») — не лучше максимума по эталонам.

## Общие фото эталонов у разных вин

В индексе 24 группы байт-идентичных основных эталонов (48 slug). По этикетке на фото
проверено глазами (`qwen_finetune/ref_conflicts.csv`):

- **16 групп — фото одного вина стоит и у соседа** (Az Abrau Мадраса/Баяншира, Agora Sauvignon/
  Cabernet, Шато Ай-Даниль Гренаш / Le Grand Vostock Красностоп и т.д.). При равных скорах
  побеждает slug, стоящий первым, поэтому 7 вин не находились **даже по собственному фото
  каталога** (Мадраса, Agora Sauvignon, Гренаш, ESSE Muskat, Legato Мцване, Ветер в травах,
  Бюрнье Вионье). Чужой эталон теперь выкидывается в `build_index.py` (`drop_main`): все 16
  находятся по своему фото, на тесте 93.4% без изменений (0/0 — эти вина в тесте спасали
  доп. эталоны). Для всех 15 вин, оставшихся без эталона, найдены свои фото (добавлены как доп. эталоны,
  `data/extra/<slug>/manual_web.*`) — все 2103 вина в индексе.
- **8 групп — честные дубли** (одно вино под двумя slug или соседние винтажи с одинаковой
  этикеткой): различить по фото нельзя, оставлены как есть (`keep`).

**Дубли каталога в целом.** Кроме общих фото, в каталоге 55 групп (115 slug), где позиции
отличаются только годом, крепостью, суффиксом `-1` или написанием винодельни
(`data_prep/catalog_duplicates.csv`). На тесте они стоят 4 кадра из 379 (все — Brut d'Or Blanc
de Blancs 12% / 12.5%): 93.4% строго, **94.5%**, если ответ из той же группы считать верным
(`check_service.py --dups`). Моделью это не решается — нужен ответ организаторов, засчитывают ли
они любой slug группы.

## Сервис

`service/app.py` по умолчанию работает на прод-конфигурации Qwen (`WINE_BACKEND=qwen`,
прежний SigLIP2 — `WINE_BACKEND=siglip`). Контракт организаторов не менялся: POST
`/v1/eval/predict` с полем `image` -> `{"slug": "..."}`.

- `qwen_finetune/build_index.py` собирает `results/index_prod.npz`: 2102 основных + 1991 доп.
  эталон, из кешей прогонов (те же векторы, что дали 93.4%) или пересчётом.
- `service/qwen_finder.py` — запрос целым кадром на 2560 токенах, максимум по эталонам вина.
  Уменьшение входа до 1280px для Qwen убрано (режутся только снимки больше 4096px), иначе
  сервис считал бы не то, что измерено.
- `service/check_service.py` гоняет тест через HTTP, как скрипт организаторов: top-1 по
  кадрам с дедупликацией по SHA-256 (§11.48), по винам, латентность против таймаута 10 с.

**Деплой.** На поде: `build_index.py` -> `check_service.py` -> `bash service/make_bundle.sh`
собирает `wine_prod.tar` (код, адаптер, индекс, карточки вин, код Qwen3-VL-Embedding; веса модели
~17 ГБ качаются с HF при первом запуске, `WITH_WEIGHTS=1` — положить в пакет). На сервере:
распаковать и `bash service/run_prod.sh` (порт 8080, нужен GPU с bf16 и ~20 ГБ видеопамяти).

**«Вина нет» в контракте.** Скрипт организаторов записывает невалидный slug как
`predicted_slug: null`, а метрику считают они. Что засчитывается для фото без вина, в
README не сказано. Поэтому порог в `/v1/eval/predict` включается переменной
`NO_WINE_THRESHOLD=0.60` и **по умолчанию выключен**: если фото без вина в тесте нет или
null для них не считается верным, отказ только теряет балл. `/v1/search` отдаёт признак
`no_wine` по порогу 0.60 всегда — для интерфейса. Вопрос организаторам: будут ли в тесте
фото без вина и какой ответ для них верный (`null`, пустая строка, особый slug).
