# Серверный инференс: refined-7db54690044e

Самостоятельный перенос проверенного серверного пайплайна, без админки,
фотографий, базы сканов и зависимости от исследовательского окружения.
Python 3.12; Linux и macOS; ONNX Runtime CPU. GPU и PyTorch для запуска не нужны.

## Установка и веса

Из корня репозитория:

```bash
python3.12 -m venv .venv-portable
source .venv-portable/bin/activate
python -m pip install -r portable/requirements.txt
```

Прямые и транзитивные зависимости закреплены; `requirements-tested.txt`
содержит версии из проверенного чистого окружения Python 3.12 на macOS ARM64.
Контейнерный рецепт предусмотрен для Linux; проверка этой поставки проводится
нативно на macOS, Docker-образ отдельно не проверялся.

Скачайте отдельно `refined-7db54690044e.zip`, размещённый владельцем проекта
на диске, и `refined-7db54690044e.zip.sha256`. В Git хранятся только код,
описание и контрольные суммы. Публичная ссылка на диск ещё не назначена.

```bash
# Выполнить в папке с двумя скачанными файлами:
shasum -a 256 -c refined-7db54690044e.zip.sha256

# Из корня репозитория; замените путь к архиву:
mkdir -p models
unzip /path/to/refined-7db54690044e.zip -d models
python -m portable.assets
```

В результате получится `models/refined-7db54690044e/`. Можно хранить модель
вне репозитория и указать путь через `WINE_MODEL_DIR` или CLI `--model-dir`.
При запуске сверяются SHA-256 **всех девяти файлов** с
[`model_manifest.json`](model_manifest.json); неполный или другой комплект
не загрузится. OCR получает явные пути к локальным весам и не скачивает их.

В комплекте:

| Файл | Для чего нужен |
|---|---|
| `encoder.onnx` | SigLIP 2 base patch16/256 и обученная проекция, FP32 |
| `yolo.onnx` | YOLO11n для выбора центральной бутылки |
| `ocr/PP-OCRv6_det_small.onnx` | Детекция текста |
| `ocr/ch_ppocr_mobile_v2.0_cls_mobile.onnx` | Ориентация строк текста |
| `ocr/cyrillic_PP-OCRv5_rec_mobile.onnx` | Распознавание кириллицы |
| `index.npz` | Визуальные векторы каталога |
| `geometry.npz` | Локальные дескрипторы эталонов |
| `index.json` | Slug, каталог, OCR эталонов и коэффициенты реранкинга |
| `provenance.json` | Происхождение и контрольные суммы исходной поставки |

Одного `encoder.onnx` недостаточно: нужны весь индекс, метаданные и OCR.
Комплект содержит 2 034 доступных slug и 2 080 эталонов при каталоге из
2 103 позиций. Он заморожен для воспроизводимости сравнения; последние
ручные изменения папки `images` в него автоматически не попадают.
Это экспорт для инференса, не checkpoint для продолжения обучения.

## Запуск

```bash
# Один файл; полный JSON выводится в stdout.
python -m portable.predict /path/to/photo.jpg --output outputs/prediction.json

# API (один процесс, чтобы не дублировать веса в памяти).
uvicorn portable.app:app --host 127.0.0.1 --port 8080 --workers 1
```

Альтернативное расположение модели:

```bash
export WINE_MODEL_DIR=/absolute/path/to/refined-7db54690044e
python -m portable.assets
uvicorn portable.app:app --host 127.0.0.1 --port 8080 --workers 1
```

- `GET /health`: готовность, версия модели, размер индекса.
- `POST /v1/eval/predict`: multipart-поле `image`; строго `{"slug":"..."}`.
- `POST /v1/predict`: slug, карточка и ссылка на портал, top-5 разных slug,
  оценки ранжирования, отрыв, OCR, области изображения и время этапов.
- `/docs`: интерактивная документация API.

```bash
curl -F image=@/path/to/photo.jpg http://127.0.0.1:8080/v1/eval/predict
```

Читаются JPEG, PNG, WebP и другие форматы Pillow. EXIF-поворот исправляется,
вход переводится в RGB без дополнительного изменения размера перед моделью.
Предел загрузки — 24 MiB и 64 мегапикселя; повреждённые файлы дают 422,
слишком большие — 413. Изображения и история запросов не сохраняются.
Первый запрос включает холодный инференс. Параллельные запросы ждут очередь;
время ожидания не включено во внутреннее поле `latency_ms`.

Для контейнера (команды из корня репозитория):

```bash
docker build -f portable/Dockerfile -t wine-portable .
docker run --rm -p 127.0.0.1:8080:8080 \
  -v "$PWD/models/refined-7db54690044e:/models:ro" wine-portable
```

API предназначен для локального запуска или размещения за шлюзом приложения;
авторизации и админки в этом модуле нет. Действующий сервер этой поставкой
не обновляется.

## Пайплайн

1. YOLO11n выбирает ближайшую к центру бутылку; при отсутствии детекции
   используется полный кадр. Отдельная эвристика сохраняет тело бутылки,
   если на студийном фото детектор выделил только горлышко.
2. RapidOCR 3.9.2: PP-OCRv6 detector, PP-OCRv2 classifier,
   PP-OCRv5 Cyrillic recognizer. Текст помогает определить область этикетки.
3. SigLIP 2 с проекцией кодирует бутылку и дополнительную область этикетки.
   Размер входа энкодера 256×256; точный косинусный поиск по индексу.
4. Объединяются визуальные и текстовые кандидаты. TF-IDF по символьным
   n-граммам, транслитерация, совпадение сорта/года, RootSIFT и геометрическая
   проверка дополняют визуальное сходство. Фиксированный линейный реранкер
   возвращает top-5 и лучший slug. Здесь нет LightGlue или VLM.

`score` и `similarity` не являются вероятностями. Open-set не откалиброван:
даже для отсутствующего вина возвращается ближайший доступный slug.

## Основание выбора и ограничения оценки

Сравнение 24.09.2026: 39 фотографий с ручными slug для 28 вин из папки
«Реальные фото». Остальной 61 снимок без меток в точность не входит.
Веса и индексы были заморожены, проверочные снимки и их найденные копии
в них не включались. Нового обучения при упаковке не было.

| Вариант | Автоматический top-1 |
|---|---:|
| Этот серверный ONNX | **25/39 — 64.1%** |
| Прежний Mac | 24/39 — 61.5% |
| Новый поиск, прежние веса | **25/39 — 64.1%** |
| Обученная проекция | 23/39 — 59.0% |
| Частичное дообучение SigLIP 2 | 24/39 — 61.5% |

У этого варианта автоматический recall@5 — 27/39 (69.2%), macro-F1 по
28 целевым классам — 59.7%. Один истинный slug отсутствует в индексе и
считается ошибкой. Диагностика с ручной областью этикетки дала 31/39 (79.5%),
но это **не автоматическая точность** и такой режим не включён в API.
Машиночитаемая сводка: [`evaluation.json`](evaluation.json).

Результат относится к небольшой выбранной по наличию разметки выборке,
использованной для сравнения моделей, а не к новому независимому тесту.
Пайплайн `retrieval/` этого репозитория на этих же 39 снимках в данном
эксперименте не проверялся: его 85.7% на 56 других фото с этими числами
сопоставлять нельзя. Гарантии 100% распознавания нет.

## Проверка переноса

```bash
python -m pip install -r portable/requirements-dev.txt
python -m pytest portable/tests -q

# Дополнительно, если есть исходная папка «Реальные фото»:
WINE_TEST_IMAGES_DIR=/path/to/real_photos python -m pytest portable/tests -q
```

Обычные тесты проверяют HTTP-контракт, EXIF/RGB, повреждённый файл, предел
размера и контрольные суммы. Интеграционный тест проверяет SHA-256 трёх
реальных снимков и совпадение top-1, top-5 и OCR с зафиксированными ответами
серверного варианта от 24.09.2026. Сами снимки в Git не включены.
