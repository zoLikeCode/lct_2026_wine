# Рекомендации: API для фронтенда

Как устроены рекомендации, какие эндпоинты звать и что где показывать (`backend/recsys.py`,
`backend/recsys_service.py`, `backend/taste.py`). Анкета, экран «Мой вкус», свайп и вкус вина в карточке уже
сделаны на фронте — `dist/taste.js`, `dist/taste.css`.

**Коротко про логику.** Рекомендации строятся по коллекции пользователя: оценки 4–5 и бутылки, которые он
открывал или держит дома, — «нравится»; оценки 1–2 и «Не то» — «не нравится». Избранное и сканы вкус не
меняют (это «хочу попробовать», а не «нравится»). Новичку, пока у него ничего нет, помогает короткая анкета.
У каждого вина в ответе есть `reason` — готовая строка «почему», её нужно показывать.

Все запросы — с тем же cookie профиля, что и остальное `/api/product/*`, ответы `Cache-Control: no-store`.
POST-запросы — JSON, тело до 8 КБ, тот же Origin.

## Карточка вина в ответах

Везде, где ниже написано «карточки», элемент списка — обычная карточка из `/api/product/wines/{slug}` плюс
поля рекомендации:

```json
{
  "slug": "adagum-valley-saperavi", "name": "Adagum Valley Saperavi", "winery": "Olymp Winery",
  "category": "Красное сухое", "region": "Кубань", "grapes": "Саперави", "description": "…",
  "alcohol": 13.5, "temperature": "16-18 °C", "pairings": ["Мясо и стейки", "Сыры"],
  "image": "/api/product/wines/adagum-valley-saperavi/image", "portal_url": "https://vino-svoe.ru/wines/…",
  "average_rating": null, "rating_count": 0, "scan_count": 0, "rating": 0, "favorite": false,

  "reason": "Похоже на «Adagum Saperavi» (ваша оценка 5): сорт Саперави, черники, ежевики",
  "owned": true, "quantity": 2
}
```

`owned` / `quantity` есть только у вин, которые лежат у пользователя (режимы «Что открыть» и подборки).

## 1. Лента рекомендаций — `GET /api/product/recommendations`

| Параметр | Значения | По умолчанию |
|---|---|---|
| `mode` | `for_you` · `new` · `cellar` · `refill` | `for_you` |
| `q` | текст, до 160 символов (для `cellar` — блюдо: «к мясу», «к рыбе») | — |
| `limit` | 1–24 | 8 |

```json
{"mode": "for_you", "items": [ …карточки… ], "request_id": "3567b8…", "empty": null}
```

Если `items` пустой, в `empty` — готовый текст для пустого состояния. Его и показывать.

| Режим | Где показать | Заголовок | Что внутри |
|---|---|---|---|
| `for_you` | главная, блок рекомендаций | «Для вас» | вина под вкус, которых у пользователя ещё нет; 1–2 «попробовать новое» рядом со вкусом |
| `new` | коллекция или главная, отдельная полка | «Попробовать новое» | новый для пользователя сорт или регион, близкий по вкусу |
| `cellar` | коллекция, кнопка «Что открыть сегодня?» + поле/чипсы блюда | «Из вашей коллекции» | только его бутылки (`owned: true`), с блюдом — подходящие к нему первыми |
| `refill` | коллекция, после того как бутылка закончилась | «Закончилось» | то же вино («купить снова», поле `refill_of`) и 2–3 похожих |

Тексты пустых состояний приходят с бэкенда, например для `cellar` новичка:
«Добавьте бутылки в коллекцию — тогда подскажем, что открыть».

`/api/product/bootstrap` по-прежнему отдаёт `recommendations` (4 вина «Для вас») и теперь ещё
`recommendations_request_id`.

## 2. Отклик на рекомендацию — `POST /api/product/recommendations/feedback`

```json
{"slug": "adagum-valley-saperavi", "action": "not_for_me", "request_id": "3567b8…", "mode": "for_you"}
```

| `action` | Когда слать | Что делает |
|---|---|---|
| `click` | пользователь открыл карточку из рекомендаций | только статистика |
| `dismiss` | «Скрыть» | вино пропадает из рекомендаций на 30 дней, вкус не меняется |
| `not_for_me` | «Не то» / «Не моё» | скрывает и считается лёгким «не нравится» — похожие вина опускаются ниже |
| `undo` | «Отменить» в тосте после `dismiss`/`not_for_me` | возвращает как было |

`request_id` и `mode` — из ответа ленты, через которую пришло вино (`home` для блока на главной из bootstrap,
`list` для подборок). Ответ: `{"ok": true}`. После `not_for_me` перезапросите ленту — она сразу станет
другой: это хороший момент для демо.

## 3. Анкета новичка

`GET /api/product/taste/onboarding` — варианты ответов и уже сохранённые ответы:

```json
{
  "answers": null,
  "colors": ["белое", "красное", "оранжевое", "розовое"],
  "sweetness": ["полусладкое", "полусухое", "сладкое", "сухое"],
  "dishes": ["BBQ", "Блюда из птицы", "Мясо и стейки", "Рыба и морепродукты", "Сыры", "…"],
  "tiles": [
    {"id": "light_fresh", "label": "Лёгкое и свежее"},
    {"id": "fruity_soft", "label": "Фруктовое и мягкое"},
    {"id": "rich_oak", "label": "Насыщенное, с дубом"},
    {"id": "aromatic", "label": "Ароматное, цветочное"},
    {"id": "dessert", "label": "Сладкое, десертное"},
    {"id": "bubbles", "label": "Игристое"}
  ]
}
```

`POST /api/product/taste/onboarding` — сохранить (всё необязательно, значения только из списков выше):

```json
{"colors": ["красное"], "sweetness": ["сухое"], "dishes": ["Мясо и стейки"], "tiles": ["rich_oak"], "sparkling": false}
```

Лимиты: `colors`, `sweetness` до 4, `dishes` до 6, `tiles` до 3. Ответ — сохранённые ответы и сразу новая
лента: `{"ok": true, "answers": {…}, "recommendations": {"mode": "for_you", "items": […], …}}`.

Что делает: цвет и сладость из анкеты фильтруют ленту, пока у человека нет своих оценок; плитки работают
как «понравившиеся вина», причина в карточке — «Под ваш вкус: насыщенное, с дубом». Когда появятся 3–4
своих оценки, анкета перестаёт влиять сама. Анкету можно пройти заново тем же POST.

Предложение: 3 экрана — цвет и сладость → «что из этого звучит вкусно» (плитки) → еда. Кнопка «Пропустить»
на каждом. Показывать при первом заходе или в пустом блоке «Для вас».

## 3а. Анкета вкуса (как у Vivino) — `/api/product/taste/quiz`

Шесть бытовых вопросов вместо выбора «цвет/сладость»: вино, кофе, шоколад, сок, сахар в чае, аромат. Каждый
ответ сдвигает оси вкуса (тело, танины, сладость, кислотность, дуб), ароматы, цвет и сладость. Вместе они
становятся одним «виртуальным понравившимся вином». Вопросы и тексты «Это говорит нам о следующем» лежат в
`backend/taste.py` (`QUIZ`).

`GET /api/product/taste/quiz` возвращает `{"questions": [{"id", "title", "options": [{"id", "label", "icon", "insight"}]}], "answers": {…}}`.

`POST /api/product/taste/quiz` принимает все шесть ответов, например
`{"answers":{"wine":"red","coffee":"black","chocolate":"dark","juice":"apple","sugar":"none","aroma":"berries"}}`.
Неполная или некорректная анкета возвращает 422 и не меняет сохранённый профиль.
Ответ: `{"ok": true, "answers", "passport", "recommendations"}`; в `passport` добавлен `quiz_complete`. Он становится `true` только после финального POST всех шести ответов (версия анкеты и время завершения сохраняются отдельно). Старые ответы подставляются в форму, но не пропускают её автоматически.
Цвет и сладость из анкеты
фильтруют ленту, пока своих оценок мало; причина в карточке — «Под ваш вкус: красное, насыщенное, сухое, красные ягоды».
Шесть ответов весят чуть меньше одной оценки 5, так что реальные оценки быстро берут верх.

## 3б. Винный свайп — `/api/product/taste/swipe`

`GET /api/product/taste/swipe?limit=10` — следующие вина колоды: те же подборки, что «Для вас», без уже пролистанных и оценённых;
у каждого вина есть `taste` (см. ниже). Ответ: `{"items", "request_id", "swiped", "liked", "empty"}`.
До завершения анкеты получение колоды и новый свайп возвращают 409. Старые неполные анкеты
сохраняются, но для свайпа их нужно завершить. Отмена ранее сделанного свайпа доступна.

`POST /api/product/taste/swipe` принимает `{"slug": "…", "verdict": "like" | "nope" | "skip" | "undo"}`:

| `verdict` | Что значит | Что делает |
|---|---|---|
| `like` | вправо, «хочу попробовать» | слабое «нравится» (+0.35, слабее любой оценки), вино попадает в «Лайки» |
| `nope` | влево, «не моё» | слабое «не нравится» (−0.4), вино пропадает из ленты |
| `skip` | дальше | только убирает из колоды |
| `undo` | «вернуть» | как будто свайпа не было; лайк, поставленный свайпом, снимается |

Ответ: `{"ok": true, "passport": {…}}` — паспорт сразу обновлён. Кнопка «Пробовал(а)» в колоде ставит обычную оценку
1–5 через `POST /api/product/preferences/{slug}`: это реальный отзыв, и он весит больше свайпа.

## 3в. Вкус вина — поле `taste` в `GET /api/product/wines/{slug}`

```json
{"scales": [{"axis": "body", "name": "Тело", "low": "Лёгкое", "high": "Насыщенное", "value": 4.5}, …],
 "aromas": [{"id": "dark_berries", "name": "тёмные ягоды"}], "occasions": ["ужин"], "notes": ["Выдержка в дубе"],
 "source": "По описанию, стилю и сорту винограда",
 "match": {"percent": 92, "note": "Совпадает с вашим вкусом по телу и танинам", "yours": {"body": 4.2, …}}}
```

Шкалы: тело, танины (только у тихих красных), сладость, кислотность — от 1 до 5. `match` равен `null`, пока у
пользователя нет профиля. `yours` — значения его профиля, на фронте это кольцо «ваш вкус» на каждой шкале.

## 4. Вкусовой паспорт — `GET /api/product/taste`

```json
{
  "stage": "confident", "evidence": 4.85, "liked_count": 6, "disliked_count": 0, "onboarding": false,
  "summary": "Вы любите средние по телу сухие красные вина с нотами: тёмные ягоды, красные ягоды",
  "axes": [
    {"axis": "body", "name": "Тело", "value": 3.6},
    {"axis": "acidity", "name": "Кислотность", "value": 4.0},
    {"axis": "tannin", "name": "Танины", "value": 2.4},
    {"axis": "sweetness", "name": "Сладость", "value": 1.0},
    {"axis": "oak", "name": "Дуб и выдержка", "value": 1.5}
  ],
  "aromas": [{"id": "dark_berries", "name": "тёмные ягоды", "share": 0.71}, …],
  "styles":  [{"name": "Красное сухое", "share": 0.62}, {"name": "Белое брют", "share": 0.29}],
  "grapes":  [{"name": "Саперави", "share": 0.32}, …],
  "regions": [{"name": "Кубань", "share": 1.0}]
}
```

- `axes` — для радара (паутинки), шкала 1–5 на всех осях. Оси может быть меньше пяти, если данных нет.
- `stage`: `new` — пусто, показать призыв пройти анкету или оценить вино; `learning` — подпись «Профиль
  уточняется»; `confident` — всё как есть.
- `summary` — готовая фраза под радаром.
- Обновлять после каждой оценки: радар меняется на глазах, это сильный момент демо.
- `?kind=red|white|rose|sparkling` — паспорт по одной вкладке (только вина этого стиля и анкета, если она про него).
  `tabs` — вкладки с числом понравившихся вин, `quiz` — ответы анкеты, `swiped` — сколько вин пролистано,
  `colors` — любимые цвета.

## 5. Чем дополнить коллекцию — `GET /api/product/collection/lists/{id}/suggestions?limit=6`

Для своей коллекции (`collection_lists`): подсказывает, чем заполнить свободные места. Счёт складывается из вкуса
пользователя, повода и близости к винам, которые уже лежат в коллекции. Повод берётся из названия и `goal`
(«Новый год», «Шашлыки на даче», «Подарок», «Ужин с рыбой»). Если повода в названии нет («Пятница»), что
подходить, решает состав коллекции: к игристому подскажут игристое даже новичку без оценок.

```json
{
  "list_id": "74f80e…", "free": 5, "occasion": "праздник", "request_id": "e209b4…", "empty": null,
  "items": [
    {"slug": "…", "name": "Primum Alveus Blanc De Blancs Экстра Брют 2019", "reason": "Игристое к празднику; похоже на «5 elements Брют белое»", …},
    {"slug": "…", "name": "100 оттенков красного. Саперави", "reason": "Есть у вас · ваша оценка 5; к блюдам: bbq, мясное ассорти", "owned": true, "quantity": 2, …}
  ]
}
```

- `limit` по умолчанию = число свободных мест (для подборки без размера — 6), максимум 24.
- Вина, которые уже есть у пользователя (`owned`), получают приоритет, если подходят к поводу: «соберите из того, что есть».
- Причина «похоже на «X» из этой коллекции» — когда вино ближе к вину из коллекции, чем к понравившимся.
- Другой винтаж вина, которое уже лежит в коллекции, не предлагается.
- В подсказках разнообразие стилей и не больше двух вин одной винодельни.
- Если мест нет: `items: []`, `empty: "Все места заполнены"`. Чужая коллекция — 404.
- Добавление в коллекцию — как раньше: `POST /api/product/collection/lists/{id}` с `{"action": "add", "slug": …}`.

На фронте (`dist/collection.js`): блок «Чем дополнить» (у пустой коллекции — «С чего начать») под полкой своей
коллекции, у каждого вина `reason`, «+ Добавить» и «Скрыть» (feedback `dismiss` с `mode: "list"`), клик по
карточке — feedback `click`. После добавления подсказки перезапрашиваются. Окно «Добавить вино» из коллекции
до ввода запроса показывает эти же подсказки («Подходят к этой коллекции»).

## 5б. Поиск вина для добавления — `GET /api/product/search?q=…&list_id=…`

Ответ как раньше: `{"items": [карточки]}`, до 30 вин, каждое слово запроса должно совпасть. Порядок:

1. сначала вина, у которых слова запроса есть в названии, винодельне или сорте (как раньше);
2. внутри — по тому, насколько вино подходит:
   - с `list_id` — к этой коллекции, тем же счётом, что «Чем дополнить» (вкус, повод, близость к винам в ней).
     Вина, которые уже лежат в коллекции, не возвращаются; у вина есть `reason`, если есть что сказать;
   - без `list_id` — ко вкусу пользователя (новичку — по популярности).

Раньше внутри одинаковых совпадений порядок был по алфавиту, и обрезка до 30 отсекала подходящие вина. Чужая
коллекция в `list_id` — 404. На фронте окно «Добавить вино» из коллекции передаёт `list_id` и пишет
«Найдено: N · сначала то, что подходит к коллекции».

## 5а. Коллекции для вас — `GET /api/product/shelves/for-you?limit=4`

Публичные коллекции других людей, которые пользователь ещё не сохранил, ранжированы по его вкусу так же, как
подбор коллекций в чате: средний счёт вин коллекции в ленте + доля подходящих вин. `limit` — от 1 до 12.

```json
{"items": [{…как GET /api/product/shelves/{id}…, "reason": "«5 elements Брют белое» — ваша оценка: 5 из 5"}],
 "needs_taste": false, "empty": null}
```

- Пока о вкусе ничего не известно (нет оценок, бутылок, свайпов и анкеты): `items: []`, `needs_taste: true`
  и `empty` с приглашением пройти анкету — случайную подборку новичку не показываем.
- Свои коллекции и уже сохранённые себе не попадают.

На фронте: блок «Подходят вашему вкусу» (2 коллекции) над лентой на вкладке «Сообщество» → «Все подборки»;
новичку вместо него — приглашение с кнопкой «Пройти анкету вкуса».

## 6. Сомелье-чат и рекомендации

Отдельного API нет — чат (`POST /api/product/assistant`) сам ходит в рекомендации:

- «Подбери вино к шашлыку», «что-то в моём вкусе», «белое к рыбе» — кандидаты берутся из той же ленты:
  ограничения запроса (цвет, сладость, блюдо) фильтруют, порядок — по вкусу пользователя; уже оценённые
  вина не повторяются, а к блюду могут попасть его бутылки из дома («Есть у вас: 2 бут.»). С GigaChat
  модель выбирает до трёх из этих кандидатов и получает фразу из паспорта вкуса; без GigaChat
  показываются первые три.
- «Что открыть из моей коллекции к рыбе?», «у меня дома есть вино к стейку?» — ответ из своих бутылок,
  `recommendation_type: "cellar"`, карточки как обычно. Отображается тем же компонентом, что и подбор вина.
- «Подобрать с сомелье» на экране своей коллекции — чат с прикреплённой коллекцией:
  `POST /api/product/assistant` с `{"message": "Что добавить в эту коллекцию?", "intent": "collection_fill",
  "list_id": "…"}`. Кандидаты — подсказки «Чем дополнить» этой коллекции (вкус, повод, близость к винам в ней),
  суженные цветом, сладостью или блюдом из сообщения («а что-нибудь розовое?»). У GigaChat свой системный промпт
  (`COLLECTION_FILL_PROMPT` в `backend/product.py`): он видит название и повод коллекции, её вина, вкусовой паспорт
  и кандидатов, выбирает до трёх только из кандидатов и может ответить о винах, которые уже в коллекции. Без
  GigaChat — первые три подсказки с причинами. Ответ: `recommendation_type: "collection_fill"`, `list_id`, карточки
  с `reason`; на фронте у каждой кнопка «+ В коллекцию». Коллекция остаётся прикреплённой, пока её не уберут.
  Чужая коллекция — 404, без `list_id` — 422.

## Что стоит показать на фронте в первую очередь

1. `reason` под карточкой в блоке «В вашем вкусе» / «Откройте новое» на странице коллекции — сейчас он
   виден только в чате, а это главное объяснение «почему».
2. Кнопка «Не то» на этих карточках (feedback `not_for_me`) и перезапрос блока.
3. Анкета новичка вместо пустого блока при первом заходе.
4. Радар вкуса в профиле или коллекции.
5. «Что открыть сегодня». («Чем дополнить» в коллекции и «Коллекции для вас» уже сделаны.)

## Ошибки

| Код | Когда |
|---|---|
| 422 | неизвестный `mode`, `limit` вне 1–24, значения анкеты не из списка, неизвестный `action` |
| 404 | нет такого вина или подборки |
| 403 | чужой Origin в POST |

## Чего не делать

- Не собирать «почему» на фронте — показывать `reason`.
- Не слать запросы на каждое нажатие клавиши в поле блюда для `cellar`: по Enter или по выбору чипса.
- Не кэшировать ленту между оценками: после оценки, «Не то», добавления/открытия бутылки — перезапрос.

## Если что-то не так

`WINE_RECSYS=legacy` в окружении сервера возвращает прежнюю ленту без нового кода — на случай проблем на демо.


### Taste introduction and discussion

`GET /api/product/taste` also returns `guide_seen`. The first visit explains **Обзор**
and **Обсудить с сомелье** before the required quiz (or before swiping for a returning
profile). `POST /api/product/taste/guide` acknowledges the explanation idempotently
for the current profile. This does not complete the quiz. The acknowledgement is
preserved when merging a guest profile into an account.

`POST /api/product/assistant` accepts `intent: "taste_discussion"`. The backend reads
the current profile's quiz, ratings, likes and taste summary; it does not accept a
client-supplied passport or profile ID. `context` keeps follow-up questions in the
conversation. No scan or list ID is allowed with this intent. AI recommendations
must reference the supplied catalog candidates; an unavailable AI returns a
clearly labelled profile summary. This intent requires an authenticated account;
the one-question guest trial applies only to the general assistant.


### Доступ и карточка после скана (20.10.2026)

Без аккаунта доступны сканирование, чтение карточки вина и один вопрос сомелье. API
коллекции, сообщества, вкуса, достижений (в составе коллекции), рекомендаций и рейтингов
требуют сессию аккаунта. Запись лайков и оценок также возвращает 401 `account_required`
для гостя. Старые гостевые данные сохраняются и могут переноситься при входе.

В гостевой карточке `preferences_available=false`, `taste.match=null`. `similar` — до
трёх разных вин по известным вкусовым осям и стилю каталога, без персональных оценок.
Они не являются альтернативами распознавания и не меняют ML-результат.

Подготовленные примеры сообщества включены по умолчанию и на сервере, и локально:
6 коллекций трёх примерных авторов и 24 сообщения из `content/demo_community.json`.
Они создаются при запуске приложения только для существующих slug каталога.
`WINE_DEMO_COMMUNITY=0` явно скрывает примеры без удаления данных; `=1` включает их.
Сообщения имеют `example=true`, явно обозначены в обсуждении и не создают аккаунтов,
оценок, сканов или настоящих достижений. Повторный запуск не дублирует сообщения.
Личные коллекции и пользовательские комментарии не перезаписываются. `/api/status`
показывает в `community` только счётчики опубликованного подготовленного контента;
деплой выводит эти фактические значения сервера в GitHub Actions.
