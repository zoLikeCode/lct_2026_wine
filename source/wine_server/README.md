# Сканер вин на сервере

Адрес: https://wine.77-105-169-21.sslip.io/ · админка: https://wine.77-105-169-21.sslip.io/admin/

Сканер открывается по обычному адресу сайта без входа, кода и подключения телефона. Пароль админки находится в локальном файле `ДОСТУП.md` и не включается в публикацию сайта. Приложение работает на сервере 77.105.169.21 и не требует включённого MacBook.

## На Android

Откройте https://wine.77-105-169-21.sslip.io/ в Chrome. Можно сразу нажать «Сканировать этикетку» или «Выбрать фото». Кнопка «Установить» вызывает предложение установки, если браузер его поддерживает, либо показывает, как добавить приложение через меню Chrome. Это устанавливаемое веб-приложение (PWA), отдельного APK нет. После установки запускайте его со значка на главном экране; разрешение камеры нужно только для съёмки.

Публичны только `GET /api/status` и `POST /api/predict`. История всех сканов, исходные снимки, датасет и операции разметки по-прежнему требуют входа в админку. `WINE_SCAN_KEY` больше не нужен; обязательным остаётся `WINE_ADMIN_PASSWORD`. Старые ссылки с `#key` открывают тот же сканер без сохранения или отправки ключа.

Новый снимок обрабатывается на сервере. Карточка показывает наиболее похожее вино и альтернативы; результат не является подтверждённой меткой. Последние 24 карточки сохраняются в истории телефона и доступны без интернета. Общая история всех устройств находится в админке. Очистка истории телефона не удаляет серверные записи.

## Админка

- **История сканов.** Снимок, время, устройство, исходное предсказание и отдельно ручной slug. Кнопка «Сравнить и разметить» открывает тот же механизм, что и распределение собственных фото. Скан копируется в `images` только после «Сохранить». Оригинал скана и первоначальное предсказание сохраняются.
- **Разметка фото.** Выберите папку или несколько файлов. Оригиналы на вашем устройстве остаются на месте; загрузки сохраняются отдельно на сервере. Наведение показывает фото для сравнения, нажатие на название выбирает вино. Сохранение всегда использует последнее выделенное название. «Назад» открывает и уже распределённые снимки. Повторное сохранение с другим slug перемещает тот же файл, сохраняя его идентификатор и разметку границ.
- **Проверка папок.** Доступны все 2 103 папки, поиск и фильтр непроверенных. При включённой галочке «Только непроверенные» показываются папки минимум с двумя фотографиями в `images`, где хотя бы одна ещё не подтверждена. При выключенной галочке доступны также папки с одним фото и пустые папки. Над списком показаны «Осталось проверить» (непроверенные папки минимум с двумя фото) и общее число папок в списке; оба счётчика учитывают поиск и обновляются после сохранения или отмены проверки. Отметьте чужие фото, затем сохраните проверку: отмеченные попадут в `needs_review`, остальные будут подтверждены. Можно перейти вперёд/назад без подтверждения, включая пустые папки. «Отменить проверку» возвращает снимки последней проверки, если они не были изменены следующими действиями.
- **Границы этикетки.** По умолчанию открываются неразмеченные **реальные фото** из проверенной подборки 626 снимков (26.09.2026). Можно переключиться на все фото `images`, только размеченные или отдельную папку вина. Счётчики показывают размер выбранной подборки, уже размеченные фото и остаток, обновляются после сохранения. «Назад» возвращает и сохранённый кадр для исправления. Выделите прямоугольник или последовательно четыре угла лицевой этикетки. Углы можно двигать. «Этикетки не видно» — отдельная отметка, а не случайная пустая рамка. Есть экспорт JSON с четырёхугольниками и нормированными YOLO-прямоугольниками.

Подборка хранится в `collector/real_photo_selection.json` внутри датасета: список `items` с `image_id` и `sha256`. Это зафиксированный набор по содержимому снимков, а не фильтр по домену источника. Он включает реальные интернет-фото и собственные снимки. Смена slug не исключает фото из подборки; уход в `needs_review` исключает, как и изменение SHA-256. Новые загрузки автоматически в эту подборку не добавляются. API `/admin/api/boundaries` принимает `photo_set=real|all` (по умолчанию `all` для совместимости); `summary` содержит `total`, `labeled`, `unlabeled`, `selected`. Фильтр состояния не меняет общие счётчики, выбор slug меняет. Отсутствие файла подборки возвращает явную ошибку; подмена всеми фото не выполняется.
- **Выгрузка.** ZIP всей `images` или нескольких выбранных папок. Можно скачать только фотографии, фотографии вместе с JSON границ или только JSON. Независимый фильтр выбирает все фото, фото с разметкой этикетки либо без неё. Поиск папок работает по названию, винодельне и slug; выбор сохраняется при смене запроса. Кнопка «Выгрузить ZIP» в редакторе границ переносит текущую папку и фильтр в настройки выгрузки.

Галочка «Сразу выделить границы этикетки» включает тот же редактор при распределении фото и сканов. Координаты относятся к изображению после применения EXIF-ориентации; масштаб экрана на них не влияет. Закрытые бликом или невидимые детали не восстанавливаются автоматически.

Фотографии в `images` сохраняют прежние статусы проверки. Само присутствие в этой папке не означает подтверждение метки. Новые снимки и границы **не запускают автоматическое обучение** и не изменяют поисковый индекс текущей модели.

## ZIP фотографий и границ этикеток

Вкладка **Выгрузка → выбрать содержимое, фильтр и папки → Собрать ZIP → Скачать ZIP**. До сборки показаны количество фотографий, JSON, папок и примерный размер. Пустые выбранные папки сохраняются в структуре архива. В выгрузку входят зарегистрированные изображения из `images`; `needs_review`, ещё не назначенные сканы и загрузки в неё не входят.

«Без разметки» означает отсутствие сохранённой записи о границах, независимо от проверки slug. Отметка «Этикетки не видно» считается разметкой и выгружается как отрицательный пример (`no_label: true`). Режим «Только JSON» автоматически выбирает фотографии с разметкой. Для неразмеченных фотографий JSON не создаётся.

```text
images/<slug>/<исходное-имя>.jpg
annotations/<slug>/<исходное-имя>.jpg.json
_export.json
```

Режим «Только фотографии» содержит только `images`, без JSON. «Только JSON» содержит `annotations` и `_export.json`, без фотографий. В смешанном режиме доступны обе папки и манифест. JSON каждого фото содержит `image_path`, SHA256, slug, размер после применения EXIF, четыре угла `points` в диапазоне 0–1, `points_pixels`, прямоугольник `bbox_xyxy_normalized`, `yolo_box` (класс 0, центр x/y, ширина/высота), признак `no_label`, версию и время сохранения. Координаты отсчитываются от верхнего левого угла **после EXIF-поворота**. Байты оригинального изображения и его EXIF не меняются: при обучении нужно применить EXIF перед использованием координат. `_export.json` перечисляет выбранные файлы, контрольные суммы, состояние проверки slug и параметры выгрузки.

Сборка выполняется в фоне одним заданием, ZIP64 поддерживает большие датасеты. Можно продолжать разметку или закрыть вкладку: изображения и JSON фиксируются согласованным снимком на момент начала сборки. Все фото проверяются по SHA256; несовпадение или отсутствующий файл останавливает сборку вместо выдачи неполного архива. Большие ZIP скачиваются напрямую, без загрузки целого архива в память браузера; поддерживается HTTP Range.

Архивы доступны только после входа в админку. Готовый архив хранится 24 часа; скачивание продлевает срок ещё на сутки. Просроченные архивы удаляются при обращении к списку/скачиванию, создании архива или запуске сервиса. Можно удалить ZIP вручную, не затрагивая исходные фото и разметку. Одновременно хранятся до пяти архивов; перед сборкой проверяется свободное место с запасом 1 ГБ. После перезапуска сервера готовые архивы остаются доступны, прерванный архив нужно собрать заново.

## Модель и ограничения

Основа — ранее выбранная версия `refined-7db54690044e`: YOLO11n → бутылка и область этикетки → дообученный SigLIP 2 base patch16/256 с проекцией → точный поиск → SIFT/RANSAC, признаки текста и обученный ранжировщик `learned_all`. Индекс содержит 2 034 slug и 2 080 эталонов. Каталог админки содержит 2 103 slug. Перенос всех папок не расширяет замороженный индекс автоматически.

Визуальные веса экспортированы в ONNX FP32 без квантования. Максимальная ошибка эмбеддингов относительно PyTorch на шести проверочных изображениях — около 0,000002. Исходный индекс и параметры ранжирования сохранены.

Apple Vision недоступен на Linux. На сервере используется локальный RapidOCR 3.9.2: PP-OCRv6 small для поиска текста и Cyrillic PP-OCRv5 mobile для чтения. Поэтому версия явно помечена `linux-onnx-fp32-ppocr5-cyrillic`. Старые показатели Mac-версии нельзя автоматически приписывать серверной. Диагностическая проверка переноса на прежнем validation сохраняется в `reports/portable_validation.json`; это не независимая оценка на магазинной съёмке. На тех же 150 запросах переносимая версия дала 139 верных top-1 (92,67%), прежняя Mac-версия — 137 (91,33%). Recall@5: 97,33% против 98%. Файлы запросов сверены по SHA256; проверочных сбоев нет. Небольшая разница не доказывает превосходство на новых фото.

Сервер: 2 vCPU, около 2 ГБ RAM, без GPU. Обрабатывается один запрос одновременно; следующий получает понятное сообщение о занятости. На шести запросах после первого запуска обработка занимала 4,1–6,9 с; первый запрос — 7,5 с. Это небольшая проверка работоспособности, не нагрузочный p95 и не выполнение прежней цели 3 с. Подробности — `reports/remote_smoke_benchmark.json`. Время загрузки фото по мобильной сети добавляется отдельно.

## Хранение и запуск

```text
/opt/wine/
  wine_server/                  # API, интерфейсы и models
  wine_curation/curation.py      # операции с файлами и журналом
  wine_dataset/
    images/<slug>/
    needs_review/<slug>/
    collector/state.sqlite3     # метки, сканы, загрузки, границы, журнал
    curation/                   # служебные экспорты и резервные копии
    catalog.csv
    manifest.csv
    coverage.csv
  wine_media/
    scans/                      # фото сканов до и после ручного назначения
    uploads/                    # ещё не распределённые загрузки
  venv/
```

Служба `wine.service` автоматически запускается после перезагрузки и восстанавливается после сбоя. Приложение работает от отдельного пользователя `wine` на 127.0.0.1:8100. Снаружи доступны SSH (22) и nginx (80/443). Старый проект удалён, Docker и containerd остановлены и отключены.

HTTPS выдан Let's Encrypt, продление настроено через системный certbot. Технический адрес использует DNS sslip.io. Секреты находятся только в `/etc/wine.env`, доступном root. Авторизация сканера — персональная ссылка, админки — отдельный пароль и защищённая cookie. Фотографии, база и разметка не раздаются как открытые статические файлы.

```bash
# Состояние и последние события
ssh root@77.105.169.21 'systemctl status wine --no-pager'
ssh root@77.105.169.21 'journalctl -u wine -n 50 --no-pager'

# Обновить только код и интерфейсы; текущие данные и секреты не перезаписываются
bash outputs/wine_server/deploy/publish.sh

# Проверить все зарегистрированные фото, контрольные суммы и папки
ssh root@77.105.169.21 '/opt/wine/venv/bin/python /opt/wine/wine_server/scripts/verify_dataset.py'

# Сделать согласованную копию базы с историей и границами
ssh root@77.105.169.21 'runuser -u wine -- /opt/wine/venv/bin/python /opt/wine/wine_server/scripts/backup_metadata.py'
```

Резервная копия базы не дублирует фотографии. Для полного переноса нужны одновременно база, `wine_dataset/images`, `wine_dataset/needs_review` и `wine_media`. Нельзя заливать старый `state.sqlite3` поверх рабочей базы: это затрёт последующую серверную разметку и историю. Первоначальный снимок метаданных из `snapshot_dataset.py` предназначен только для первого развёртывания.

## Проверки

### Разметка в форматах Roboflow / YOLO / COCO

Во вкладке **Выгрузка** выберите «Фотографии + разметка» или «Только разметка» и формат:

- **COCO JSON**: `_annotations.coco.json` с `images`, `categories`, `annotations`; пиксельные `bbox` в формате x/y/width/height и `segmentation` с сохранёнными вершинами. Класс `front_label`, ID 0. Отрицательные примеры имеют запись изображения без объекта.
- **YOLO — прямоугольники**: `labels/<id>.txt`, строки `0 x_center y_center width height`, нормированные координаты.
- **YOLO — контуры**: `labels/<id>.txt`, строки `0 x1 y1 x2 y2 ...`, нормированные координаты.
- **Исходный JSON**: прежний формат и структура папок сохранены для совместимости.

YOLO содержит `data.yaml`. В стандартных форматах файлы получают уникальные имена по ID; `_export.json` связывает их с исходными путями, slug и SHA256. EXIF-поворот применяется к экспортируемым пикселям без изменения исходников; повёрнутые фото сохраняются в PNG без потерь. Остальные поддерживаемые изображения сохраняют исходные байты. Разметку заново создавать не нужно.

Стандартные форматы включают только фотографии с сохранённой разметкой, в том числе явно отмеченные «Лицевая этикетка не видна». Неразмеченные изображения не превращаются в отрицательные примеры. «Только разметка» не содержит фото и ссылается на имена стандартного экспорта, а не исходные имена в папках slug.

«Без разбиения» предназначено для импорта; независимой валидации в нём нет. Вариант **70/15/15** создаёт `train`, `valid`, `test`, требует минимум три независимые группы и использует seed 42. Один slug и точные файловые/пиксельные дубли остаются в одной части; пропорция применяется к группам, поэтому доли фотографий могут отличаться. Похожие кадры и связанные серии автоматически не объединяются: перед оценкой качества необходимо проверить утечки между частями.

Форматы сверены с [COCO JSON](https://roboflow.com/formats/coco-json) и [Ultralytics YOLO](https://docs.ultralytics.com/guides/data-collection-and-annotation). Проверки: `tests/test_annotation_formats.py`, `tests/formats_browser_qa.cjs`.

Проверены авторизация и закрытость фотографий, испорченные загрузки, сохранение сканов отдельно от датасета, перенос/исправление slug, сохранность границ при переносе, EXIF-ориентация, конфликт версий разметки и возврат ошибочных фото в `needs_review`.

Браузерные сценарии проверены на 1440, 1024, 390 и 360 CSS px. Изолированная проверка изменяет только искусственный тестовый датасет. Проверка опубликованной версии создаёт тестовые сканы, но не меняет реальные метки. Проверены HTTPS, чтение реальной карточки, офлайн-история PWA и все разделы админки. Физическая установка на конкретный Android выполняется пользователем.

```bash
work/wine_mvp_env/bin/python -m unittest discover -s outputs/wine_curation/tests -v
work/wine_mvp_env/bin/python -m unittest discover -s outputs/wine_server/tests -v
```

Отчёты лежат в `reports/`, контрольные суммы моделей — в `models/provenance.json`. Интерфейс использует названия, характеристики и фотографии из существующего каталога; новые товарные характеристики не сочинялись.

Выгрузка проверена отдельно: 12 серверных тестов, скачивание фото/JSON и фильтры в браузере на четырёх ширинах экрана, затем повторная проверка на рабочем сервере. Полный ZIP из 8 247 фото и 2 103 папок собран за 46 секунд; все 8 247 файлов внутри архива прочитаны с проверкой CRC и SHA256. Отчёты: `reports/exports_browser/result.json`, `reports/remote_exports_browser/result.json`, `reports/remote_exports.json`.

## Дубли фото в разных винах

Вкладка **Дубли фото** ищет в `images` снимки, зарегистрированные в двух или нескольких slug. Группа определяется по совпадению SHA256 файла или хэша декодированных пикселей из каталога. Похожие этикетки, другой ракурс, кроп или пересжатая версия с изменёнными пикселями автоматически не объединяются. Файлы из `needs_review` в очередь не включаются.

Слева — очередь и число оставшихся групп, в центре — спорный снимок и его копии, справа — вина и другие фото из их папок. Общий конфликтующий снимок не выдаётся за независимый эталон. Если другого изображения нет, это указано явно. Фото можно увеличить, нажатие на название выбирает папку; **Сохранить и далее** применяет выбор. Можно найти другое вино во всём каталоге, пропустить группу или отправить все копии на повторную проверку.

Копии в выбранном slug остаются в `images`; остальные перемещаются в `needs_review/<исходный slug>`. Если выбран новый slug, туда переносится одна копия лучшего разрешения. Файлы не удаляются, совпавшие имена не перезаписываются. **Отменить перенос** восстанавливает последнее действие этой вкладки, включая привязку к загрузке/скану. Идентификаторы фото и разметка границ сохраняются; исходное предсказание сканера не изменяется. Если с момента открытия группу изменили в другом окне, сохранение останавливается до обновления.

Проверка операций: `tests/test_duplicates.py` — точные и пиксельные дубли, независимые превью, поиск, права доступа, перенос в существующий/новый slug, коллизии имён, сохранность границ, история сканов, устаревшая группа и отмена. `tests/serve_duplicates_fixture.py` запускает изолированную админку с искусственными данными на 127.0.0.1:8200 для ручной проверки интерфейса. Реальные фотографии эта проверка не меняет.

Эталоны с `source=vino-svoe.ru` или `kind=catalog_reference` исключены из групп дублей и из операций их разрешения. Другие снимки того же slug остаются в очереди. Портальное изображение может показываться справа как защищённый эталон для сравнения; его переносить эта вкладка не будет.

`python scripts/audit_duplicates.py --root /opt/wine/wine_dataset --out /tmp/wine_duplicate_audit` выполняет отдельный анализ без изменений базы и фотографий: заново считает SHA-256 файлов, дополнительно сравнивает копии побайтово и сравнивает полноразмерные RGBA-пиксели с учётом EXIF. Отчёты `audit.json`, `REPORT.md` и `report.html` разделяют images, needs_review, эталоны портала и остальные фотографии; показывают повторы внутри одного slug и между несколькими. Это анализ, а не команда удаления.

## Мобильный продукт — обновление 29 сентября 2026

Главная страница содержит сканер/загрузку фото, карточку вина, коллекцию с избранным и оценкой 1–5, реальные рейтинги по сканам и пользовательским оценкам, помощника с текстовым запросом и браузерным голосовым вводом. Старые локальные карточки сканов сохраняются. Установка PWA не требует подключения телефона или ключа.

`product.py` добавляет изолированные анонимные профили: HttpOnly Secure SameSite=Lax cookie и таблицы `wine_profiles`, `wine_preferences`, `wine_profile_scans` в существующей SQLite. Профиль принадлежит браузеру; синхронизации между устройствами без аккаунта нет. Фото завершённого скана доступно его владельцу по проверяемому профилем URL и администратору. Публичные картинки карточек ограничены эталонами портала; загруженные пользователями фото не выдаются через публичный каталог.

Данные карточек: исходный catalog.csv + `content/portal_wines.json` — 2035 сохранённых страниц портала с проверкой точного slug. Сочетания, температура и крепость взяты из структурированных данных. Для остальных вин недостающие поля не выдумываются. Рейтинг портала не смешивается с голосами пользователей приложения. Топ сканов учитывает подтверждённое администратором название при наличии; иначе результат распознавания. Запросы с префиксом устройства qa-/test- исключены из топа.

### Помощник

Без внешних настроек работает честно обозначенный «Подбор по каталогу»: фильтры по цвету/сладости, подтверждённым сочетаниям, поиск по тексту, предпочтения по положительным оценкам/избранному и сканам данного профиля; вина с оценкой 1–2 исключаются. Это ограниченный алгоритмический подбор, не языковая модель.

Подключение GigaChat: задать в `/etc/wine.env` `WINE_ASSISTANT_PROVIDER=gigachat`, `WINE_GIGACHAT_AUTH_KEY` (Authorization key, только на сервере), `WINE_GIGACHAT_CLIENT_ID`, `WINE_GIGACHAT_SCOPE=GIGACHAT_API_PERS`, `WINE_ASSISTANT_MODEL=GigaChat-2` и `WINE_GIGACHAT_CA_BUNDLE` (путь к корневому сертификату Минцифры). Для прикреплённого фото используется `WINE_ASSISTANT_VISION_MODEL=GigaChat-2-Pro` (это значение по умолчанию); исходный снимок перед загрузкой уменьшается до 1600 px и JPEG до 15 МБ. Клиент обменивает ключ на короткоживущий OAuth-токен и кеширует его; TLS проверяется с указанным сертификатом. Секреты не хранить в репозитории. Для другого совместимого провайдера остаются `WINE_ASSISTANT_URL` (HTTPS Chat Completions), `WINE_ASSISTANT_KEY`, `WINE_ASSISTANT_MODEL` без `WINE_ASSISTANT_PROVIDER=gigachat`. После настройки перезапустить `wine`. Модель получает текст запроса, до трёх прошлых запросов и 12 кандидатов с каталоговыми фактами/основаниями предпочтений. Фото передаётся в GigaChat только при явном прикреплении скана в помощнике; сервер проверяет принадлежность скана профилю и отправляет запрос на удаление загруженного файла после ответа. Ошибка удаления фиксируется в журнале и не заменяет ответ пользователю. Идентификатор профиля не передаётся. Модель выбирает до трёх существующих slug. Неверный ответ, чужой slug или таймаут возвращают проверяемый подбор по каталогу с явным уведомлением. Работу нужно подтверждать запросом `/api/product/assistant` с `mode=ai`: поле `assistant_mode` означает лишь наличие конфигурации.

Голосовой ввод: Web Speech API (`ru-RU`), запускается только по нажатию микрофона; транскрипт сначала попадает в редактируемое поле. Отправка — отдельным нажатием. Обработка речи зависит от браузера, Android Chrome поддерживается при наличии соответствующей службы. В неподдерживаемом браузере доступен текст/микрофон клавиатуры. Реальная запись звука на Android требует проверки на устройстве.

Новые API: GET `/api/product/bootstrap`, `/search?q=`, `/wines/{slug}`, `/wines/{slug}/image`, `/scans/{scan_id}/image` (только владелец скана), `/ranking?mode=scans|rating`, `/recommendations`, `/history`; POST `/preferences/{slug}` с rating=0..5/favorite=true|false; POST `/assistant` с message/context и необязательным `scan_id`, а для подбора блюда — с `intent=dish_pairing`. Префикс всех относительных маршрутов — `/api/product`. Изменения требуют same-origin; пользовательские оценки не требуют учётной записи, один голос на профиль.

Проверка: `python -m pytest -q tests`. Скриншоты и результаты адаптивной проверки: `reports/redesign_20260928/`. Локальная UI-проверка использует отдельный fixture и имитацию инференса, а не измеряет точность CV.

### Светлая тема и RunPod

Основной маршрут `/` использует светлую тему. Прежний адрес `/old-design` перенаправляет на `/`, маршрут `/dark-design` и его ресурсы удалены. PWA использует один манифест. Кнопка камеры включает поток и выключает его по повторному нажатию. После сканирования результат сохраняется в прежней локальной истории. Переход из результата или истории в помощник прикрепляет этот скан по `scan_id`; перед отправкой вложение можно убрать.

После распознавания верхняя часть карточки крупно показывает категории блюд из подтверждённых сочетаний портала. Кнопка «Подобрать блюдо с помощником» отправляет `scan_id` и `intent=dish_pairing`. В этом режиме помощник возвращает одно конкретное блюдо, выбранное из серверных примеров внутри категорий карточки; в ответе `recommendation_type=dish`, `dishes` содержит название примера и исходную категорию, `items=[]` — другие вина не предлагаются. GigaChat-2-Pro получает фото и выбирает только из этих примеров; при его недоступности остаётся пример по каталогу с предупреждением. Следующий вопрос «Как приготовить?» отправляется с `intent=dish_recipe` и названием блюда: помощник возвращает рецепт без карточек другого вина. Если вина или достаточно точного сочетания нет, ответ сообщает об этом без выдуманной рекомендации. Обычные запросы к помощнику и случай `no_wine` сохраняют прежнее поведение.

Сервер выбирает распознавание по `WINE_INFERENCE_BACKEND=local|runpod`. Для текущего Pod задать `WINE_INFERENCE_BACKEND=runpod` и `WINE_ML_URL=https://cjrcewr46hi8eo-8080.proxy.runpod.net` в `/etc/wine.env`; `WINE_ML_API_KEY` необязателен для открытого proxy endpoint. Браузер отправляет фото только на свой `/api/predict`, а backend вызывает `/v1/search`. `/v1/eval/predict` возвращает только slug и в UI не применяется. Полный ответ, включая `no_wine`, confidence и альтернативы, сохраняется в записи скана; исходный ответ ML остаётся в `ml_response`. При сбое модели пользователь получает повторяемую ошибку, а исходный локальный Engine доступен переключением конфигурации.

### Переносимый ZIP для другого сервера

Собрать архив с уже готовым `dist/` можно из каталога `wine_server`:

```bash
python3 deploy/portable/build_portable.py /tmp/wine-portable.zip
```

На Linux-сервере с Python 3.10–3.13 и доступом к PyPI: `unzip wine-portable.zip` (если `unzip` не установлен — `python3 -m zipfile -e wine-portable.zip .`), затем `cd wine-portable && bash start.sh`. Скрипт создаёт виртуальное окружение, чистую базу и каталог при первом запуске, после чего одним процессом поднимает API и готовый фронтенд. Архив содержит готовый `dist/` и полный исходный код сервиса в `source/`, включая HTML, CSS и JavaScript фронтенда и админки; локальный ML-пайплайн и веса модели исключены. В начале `start.sh` задаются `FRONTEND_URL` и `BACKEND_URL` (один публичный origin для сайта и `/api`), `RUNPOD_URL`, локальные `BACKEND_BIND_HOST` и `BACKEND_BIND_PORT`, при необходимости `TLS_CERT_FILE` и `TLS_KEY_FILE`. Публичной камере и установке PWA нужен HTTPS; без своего сертификата используйте обратный прокси. Значения можно передать и через переменные окружения.

Приватные `WINE_GIGACHAT_AUTH_KEY`, `WINE_GIGACHAT_CLIENT_ID`, при необходимости `WINE_GIGACHAT_CA_BUNDLE` добавляются в `.env` **после** распаковки. Архив не содержит пользовательскую базу, эталонные фото, разметку, ключи и локальные веса модели. В чистой установке карточки показывают встроенную заглушку вместо фото бутылки. Для сохранения данных и фотографий существующего сервера укажите `DATA_ROOT` на каталог, содержащий `wine_dataset/` и `wine_media/`; скрипт не перезаписывает базу. Полная инструкция и пример прокси находятся в `deploy/portable/README.md` (этот файл попадает в корень ZIP как `README.md`).
