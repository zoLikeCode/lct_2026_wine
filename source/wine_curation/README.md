# Два инструмента ручной разметки вина

## Запуск

Откройте двойным щелчком `Разметить фото.command` или `Проверить папки.command`. Используется уже установленное окружение `work/wine_mvp_env`. Окно Терминала держите открытым. Если интерфейс уже запущен, просто откройте его адрес:

- Разметка собственных снимков: http://127.0.0.1:8093
- Проверка содержимого папок: http://127.0.0.1:8094

Соответствующие самостоятельные точки входа: `assign_photos.py` и `review_slugs.py`. Общая логика и интерфейс лежат рядом, поэтому переносите всю папку wine_curation целиком. Нужны Python 3.12, FastAPI, uvicorn, Pillow. Новых зависимостей и сетевого распознавания нет. На другом компьютере установите зависимости из requirements.txt. Сервер слушает только этот компьютер.

## 1. Фото → правильный slug

1. По умолчанию открывается `/Users/forthang/Downloads/Camera`. Другую папку можно выбрать кнопкой или указать её путь. Вложенные папки также читаются. JPG, PNG, WebP, TIFF, BMP поддерживаются; HEIC — только при установленном pillow-heif.
2. Впишите название, винодельню, сорт или slug в поиск. Все слова ищутся одновременно. Наведение и клавиатурный фокус показывают фото карточки; щелчок выбирает вино. Выбранный slug явно указан под поиском.
3. Нажатие на фотографию открывает увеличенный просмотр; Escape закрывает его. Ссылка ведёт на точную карточку портала.
4. Нажмите «Перенести и далее». Снимок без изменения байтов перемещается в `wine_dataset/images/<slug>/own_<имя>`. Существующие файлы никогда не перезаписываются. При совпадении имени добавляется уникальный суффикс.
5. Галочка «Оставить оригинал» переключает действие на копирование. Копия независима от исходника. Выбор вина сохраняется для следующих ракурсов одной бутылки; перед подтверждением следующего фото проверяйте его.
6. Можно пропустить снимок или отметить «Нет в каталоге». В обоих случаях файл остаётся на месте. Переключатель «Показать отложенные» позволяет вернуться к ним и назначить slug.

Enter вне полей и кнопок подтверждает выбор, S пропускает снимок. Кнопка «Отменить» восстанавливает исходное размещение последней операции. После перезапуска прогресс сохраняется. Если исходник изменён, действие останавливается до повторного открытия папки.

Поле «Съёмка / магазин» сохраняет общую сессию. Заполняйте его осмысленно: соседние кадры одной бутылки нельзя считать независимым тестом. Результаты ручной разметки выгружаются в `wine_dataset/curation/own_labels.csv`, включая исходный путь, состояние, slug и идентификатор снимка. Эта таблица пригодна для последующего пересчёта сравнения 514 фотографий. Разметка не обновляет модель автоматически.

## 2. Проверить все фото внутри slug

Слева — поиск по всем 2 103 винам. Справа — все изображения выбранной папки без скрытой пагинации, рядом ссылка на портал. Размер плиток регулируется на компьютере; каждый снимок можно увеличить. Для больших папок страницу нужно прокрутить: все изображения не уменьшаются до нечитаемого размера ради одного физического экрана.

Отметьте «Это другое вино» у ошибочных снимков, затем «Сохранить проверку и далее». Они переместятся в `needs_review/<slug>/`; все остальные в текущей папке будут подтверждены вручную и останутся в images. Если всё правильно — «Все верно — далее». Можно пропустить папку и отменить последнюю сохранённую проверку. Переход с несохранёнными отметками показывает предупреждение. Изменение той же папки в другом окне распознаётся и требует обновления.

Пометка о таком же файле в другом slug означает возможный конфликт, а не правильность одного из вариантов. Снимок из карточки портала тоже может содержать ошибку; сверяйте название, год и видимые признаки. Папки с нулём фото доступны после отключения «Только непроверенные папки».

## Выполненный перенос

21 сентября 2026 перенесены **4 473 файла** из needs_review в images. После операции: **8 132 файла в images**, **0 в needs_review**, **2 103 папки slug**. Контрольные суммы всех 8 132 файлов проверены, потерь и перезаписи нет.

У перенесённых файлов сохранён `status=needs_review` в манифесте и базе, а `human_review=pending`. Физическая папка images теперь содержит как ранее принятые, так и ожидающие проверки файлы. Только ваше подтверждение переводит спорный снимок в accepted. Текущая подготовка ML читает status, поэтому такой перенос сам по себе не добавляет 4 473 непроверенные метки в обучение.

Реальные Camera-фотографии при разработке инструментов не перемещались и не размечались. Работающая модель, её галерея и предыдущие результаты сравнения не изменены.

## Журнал, резервная копия и восстановление

- База `collector/state.sqlite3`: исходные источники сохранены, пути обновлены. Таблицы `curation_events`, `curation_meta`, `curation_sources` хранят операции, происхождение и прогресс.
- `manifest.csv` и `coverage.csv` обновляются после операций. Покрытие различает физическое размещение и проверенность.
- `curation/before_curation/` — резервная копия базы, манифеста, покрытия и README до любых изменений.
- `curation/migration_verification.json` — проверка всех контрольных сумм после переноса.
- Операция записывается до движения файлов. При перезапуске прерванная операция завершается по журналу. Совпадение имени никогда не разрешается перезаписью.
- Отмена копирования сохраняет снятую копию в `curation/undo_archive/`, не удаляя байты. Отмена переноса возвращает файл в исходную папку, только если исходное имя свободно.
- Отмена идёт в общем обратном порядке: если последнее действие сделано в другом из двух инструментов, сначала отмените его там.

Для разработчика из корня проекта:

```sh
work/wine_mvp_env/bin/python outputs/wine_curation/assign_photos.py
work/wine_mvp_env/bin/python outputs/wine_curation/review_slugs.py
work/wine_mvp_env/bin/python -m unittest discover -s outputs/wine_curation/tests -v
```

Массовый перенос уже выполнен. Повторять `review_slugs.py --migrate-review` не нужно: этот режим перенесёт и впоследствии отклонённые вами файлы. Для отмены последнего массового переноса есть `review_slugs.py --undo-migration`; сначала должны быть отменены более поздние операции разметки. Не восстанавливайте старую SQLite-базу вручную поверх новых путей.

Старые сборщики не запускайте одновременно с ручной проверкой: они не используют блокировку curation и могут повторно применить прежние автоматические решения. Для новых сборов сначала требуется согласовать их с ручными метками. Поле session сохранено, но старые ML-скрипты пока не строят новое разбиение по магазинным сессиям — перед следующим обучением его нужно явно подготовить.
